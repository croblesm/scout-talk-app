Before OpenSpec

Foundation Plan

The one-page plan I worked from before any agent touched the repo. After this point, every change is delivered as an OpenSpec proposal — not a hand-coded step.

Goal

A CFP finder that takes a plain-English description of a talk and returns the upcoming conferences whose CFP topics match. End to end inside VS Code. No external vector store. No cloud embedding API.

Stack Choices

Layer
Choice
Why
database
SQL Server 2025
Native VECTOR(768) + VECTOR_DISTANCE. One DB for relational rows and embeddings.
embeddings
Ollama · nomic-embed-text
Free, no API key, no data egress. Apple Silicon Metal acceleration on the host.
orm
Prisma 7 + adapter-mssql
Typed bridge from TypeScript to SQL. Migrations live in the repo.
sql boundary
prisma/sql/*.sql, loaded once
App TypeScript never holds a SQL string literal. One file per query.

Data Model — one table

Relational columns for bookkeeping (slug, name, dates, location, topics, CFP window, contentHash) and one native vector column for the embedding. Unsupported("VECTOR(768)") carries the column through Prisma migrations; the actual CAST(... AS VECTOR(768)) happens in T-SQL.

Seed Pipeline

  • Read data/events.json (91 events, hand-curated).
  • Compute contentHash per row; skip embedding when the hash matches.
  • Batch the new/changed events through embedBatch() against host Ollama.
  • MERGE into Event via prisma/sql/upsertEvents.sql. Re-running on unchanged data is a no-op.

The next layer is the search UI. I want it built agentically. Plain-English proposal in, spec out, agent applies it, I approve. That is what OpenSpec gives me — and it starts on the next slide.
