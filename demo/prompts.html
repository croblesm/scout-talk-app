🤖 TalkScout: Spec-Driven Semantic Search with SQL Server 2025

🎬 Scenario Introduction

I am Carlos Robles, Principal PM for SQL developer experiences at Microsoft. Today I am showing you how I built TalkScout, a CFP finder for upcoming dev conferences. A speaker types a topic in plain English, and the app returns the top five upcoming conferences whose CFPs match, ranked by semantic similarity.

The whole project lives inside VS Code. Five tools, each doing one job:

  • SQL Server 2025 stores both the relational data and the embeddings as native VECTOR(768) columns, and ranks queries with VECTOR_DISTANCE
  • Ollama runs on my host with the nomic-embed-text model for embeddings, no cloud API key
  • Prisma 7 with the @prisma/adapter-mssql driver provides the typed bridge from TypeScript to SQL
  • The MSSQL VS Code extension handles connection, query editor, and Schema Designer
  • GitHub Copilot with OpenSpec drives the build itself, from change proposal to implementation

"For this demo, the environment is ready. Docker is running with SQL Server 2025. Ollama is up on the host with the embedding model pulled. The repo is at the pre-implement git tag: foundation in place, no search UI yet. OpenSpec is installed but no change has been proposed. That happens live, on camera, in a moment."

🎯 What We Accomplished

In this demo, we composed six tools inside VS Code to build a semantic-search application and ship it to Azure:

  • ✅ Drove the entire workflow with OpenSpec slash commands (/opsx-propose, /opsx-apply) inside GitHub Copilot Chat
  • ✅ Showed GitHub Copilot Chat in agent mode editing a real SQL file and opening the MSSQL Schema Designer with full schema awareness
  • ✅ Used SQL Server 2025's native VECTOR(768) data type and VECTOR_DISTANCE function, no separate vector database
  • ✅ Used Ollama with nomic-embed-text for embeddings, host-Metal locally and as a Container Apps sidecar in Azure
  • ✅ Used Prisma 7 with the @prisma/adapter-mssql driver to keep all SQL strings out of TypeScript
  • ✅ Used the MSSQL VS Code extension to inspect the VECTOR(768) column live and to render the Schema Designer
  • ✅ Demonstrated two semantic-search "magic moments" where the top result contained none of the query keywords
  • ✅ Deployed the same app to Azure with microsoft/azure-skills: Container Apps + Azure SQL Database free offer + Ollama sidecar, $0 on a free Azure account, no Azure OpenAI quota required

Key takeaways:

  • SQL Server 2025's VECTOR type brings AI capabilities directly into your database, no external vector store required, and works on every Azure SQL tier including free
  • Ollama works the same way locally and in Azure: a Container Apps sidecar gives you a free, key-less embedding endpoint with internal-only DNS
  • Prisma + a runtime SQL loader keeps application TypeScript free of T-SQL string literals
  • The same agentic primitive that drove local development also drove cloud deployment: read the spec, propose, apply, approve. OpenSpec for the code, microsoft/azure-skills for the platform
