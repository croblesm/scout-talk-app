# TalkScout Demo Script (8 minutes)

The on-camera teleprompter is `demo/prompts.html`. This file is the timed version with speaker notes for rehearsal.

Times are wall-clock from when recording starts. The total budget is 8:00 with at least 30 seconds of buffer (SC-004).

## 0:00 to 0:30, Hook

> *Speaker notes: smile, voice up. Look at camera, not at screen. Open with the problem statement.*

"I am Carlos Robles, Principal PM for SQL developer experiences at Microsoft. Every developer who speaks at conferences hits the same problem: where should I submit this talk? Listings sites organize events by date and region, never by topical fit. Today I want to show you how I built TalkScout, a CFP finder that takes a plain-English description of a talk and returns the upcoming conferences whose CFP topics match. End to end. Inside VS Code. In the next eight minutes."

## 0:30 to 1:30, Spec flythrough

> *Speaker notes: open VS Code Explorer panel. Open these in order, scroll briefly through each, no live edits.*

Open `.specify/memory/constitution.md`, scroll to Principle II: "ORM-First, no T-SQL in TypeScript." This is the rule TalkScout's design respects.

Open `specs/001-talkscout/spec.md`, scroll to FR-008: vocabulary mismatch must work. Highlight the requirement that semantic queries return events even when the query keywords are not in the description.

Open `specs/001-talkscout/plan.md`, scroll to the Tech Context table. Read aloud the row for SQL Server 2025 with native VECTOR(768) and VECTOR_DISTANCE.

Open `specs/001-talkscout/tasks.md`, scroll to T010 to T013, the user-story tasks. These are the work GitHub Copilot is going to do live in the next segment.

> *Voiceover during these opens: "Spec Kit treats the spec as the source of truth. The constitution sets non-negotiables. The spec captures user stories and functional requirements. The plan locks the tech stack. The tasks file is the ordered build plan. All four files were generated by Spec Kit slash commands. None of this is hand-rolled."*

## 1:30 to 2:00, /speckit.analyze (live)

> *Speaker notes: switch to Copilot Chat panel. Type the slash command. Wait for the report. Talk through it as it streams.*

Type into Copilot Chat: `/speckit.analyze`

Expected: report streams in chat. Final summary should show 0 critical, 0 high. Open `specs/001-talkscout/analysis.md` after, scroll to the metrics table. Point out that all 13 requirements have at least one task and the constitution alignment passes for every principle.

## 2:00 to 3:30, /speckit.implement (live)

> *Speaker notes: this is the centerpiece. Make sure the Explorer panel is visible alongside the chat panel.*

Type into Copilot Chat: `/speckit.implement`

What appears, in roughly this order:
- `prisma/sql/searchEvents.sql` (already exists; agent leaves it)
- `src/lib/cfp-status.ts`
- `src/app/actions.ts`
- `src/components/CfpStatusPill.tsx`
- `src/components/EventCard.tsx`
- `src/components/SearchInput.tsx`
- `src/app/page.tsx` (modified to wire components)

Expected total time: 60 to 90 seconds. While files appear, narrate: "The agent is reading tasks.md and creating exactly the files it lists. No more, no less. Each file is small because the spec is precise."

## 3:30 to 4:30, Marquee 1: Copilot inside searchEvents.sql

> *Speaker notes: open the SQL file. Position cursor on the line immediately after the WHERE clause. Type a comment slowly so the camera catches it.*

Open `prisma/sql/searchEvents.sql`. Read aloud: "Eight lines. SQL Server 2025 has a native VECTOR(768) data type and a VECTOR_DISTANCE function. The query embedding arrives as a JSON array and is cast to a vector in place."

Place cursor after `WHERE embedding IS NOT NULL`. Type the comment:

```sql
-- Filter to events whose CFP is still open today.
```

Wait for Copilot inline suggestion. Press Tab to accept.

Expected suggestion: `AND cfpCloseDate >= GETDATE() AND cfpOpenDate <= GETDATE()`

Read the inserted line aloud, then say: "GitHub Copilot working inside a TypedSQL file, against SQL Server 2025 syntax. No plugin tax. No copy and paste."

> *Speaker notes: undo the change before moving on (Cmd+Z). We want the file clean for the next take.*

## 4:30 to 5:00, Clean TypeScript moment

> *Speaker notes: open actions.ts. Hover the searchEvents import.*

Open `src/app/actions.ts`. Read aloud: "Six lines of business logic. One embed call, one typed query. The application code never contains a SQL string. Prisma's TypedSQL approach turns the .sql file into a runtime-loaded constant the function can pass through."

Hover the import for `SEARCH_EVENTS_SQL` from `@/lib/sql`. Show the inferred type briefly, then close.

## 5:00 to 5:30, Marquee 2: MSSQL extension query editor

> *Speaker notes: switch to MSSQL VS Code extension panel. The talkscout connection should already be saved.*

Click the connect icon on the saved `talkscout` connection. Open a new query window.

Paste:

```sql
SELECT TOP 3
    name,
    topics,
    CAST(embedding AS NVARCHAR(80)) AS embedding_preview,
    VECTORPROPERTY(embedding, 'Dimensions') AS dims
FROM Event
ORDER BY name;
```

Press F5. Read aloud: "Three rows. The embedding column is real, dimension 768, just sitting there in SQL Server. No extension. No external service. Native."

## 5:30 to 6:00, Magic moment 1

> *Speaker notes: switch to the browser at localhost:3000. The page should be clean. Click into the search input.*

Type: `agentic workflows for databases`

Press Enter. Wait roughly 1 to 2 seconds for results to render.

Read the top result name aloud. Then say: "The word 'agentic' is not in the title. Not in the topics. Not in the description. The embedding model and SQL Server's vector distance figured out this is what I meant."

## 6:00 to 6:30, Magic moment 2

> *Speaker notes: clear the input. The placeholder should resume cycling.*

Type: `type safety across the stack`

Press Enter. Wait for results.

Read the top result name aloud. Say: "Same trick, different topic. Vocabulary mismatch handled by semantic search."

## 6:30 to 7:00, Cross-surface cameo

> *Speaker notes: open the integrated terminal. Type slowly so the camera catches it.*

Type: `copilot`

When the interactive prompt appears, type: `/speckit.analyze`

Let it stream for roughly 15 seconds. Cut before it finishes. Say: "Same workflow, different surface. The Copilot CLI executes the same Spec Kit slash commands the chat panel does."

## 7:00 to 7:30, Schema Designer cameo (optional, if running on time)

> *Speaker notes: skip this if the clock shows we are behind.*

Right-click the `Event` table in the MSSQL Object Explorer. Choose "View Schema Designer." Linger 10 seconds. Say: "Same MSSQL extension, schema designer view. Prisma owns the migrations here, but if you wanted to inspect or edit the table layout visually, this is one click away."

## 7:30 to 8:00, Wrap

> *Speaker notes: back to camera. Voice up. Smile.*

"That is TalkScout. Eight minutes from spec to working semantic search, end to end inside VS Code. SQL Server 2025 stored the vectors. Prisma kept the TypeScript clean. GitHub Copilot, with Spec Kit, drove the build. Repo and links are below. Thanks for watching."

End recording.
