What We Did Today

Eight minutes from change proposal to working semantic search, end to end inside VS Code.

What this stack gives you

An end-to-end semantic-search application inside VS Code, with no separate vector database, no cloud embedding API, and no SQL string literals in TypeScript. Five tools, each doing one job. Eight minutes from change proposal to working app.

Tool
Job in this project
Why it earns its place
SQL Server 2025
Stores 91 conferences with 768-dim embeddings as native VECTOR(768); ranks queries with VECTOR_DISTANCE
One database for relational AND vector data. No Pinecone + Postgres dual setup.
Ollama (host)
Generates 768-dim embeddings via nomic-embed-text for seed and search
Local, free, no API keys, no data egress. Metal-accelerated on Apple Silicon.
Prisma 7
Migrations, Event model, typed bridge from TS to SQL via @prisma/adapter-mssql
Schema-as-code. T-SQL stays in prisma/sql/; the call site reads as one line.
MSSQL VS Code extension
Connection management, query editor, results grid, Schema Designer
Inspect VECTOR(768) data live in the IDE. No external tooling.
GitHub Copilot + OpenSpec
/opsx-propose generates a change spec from plain English; /opsx-apply writes the code
Spec-driven. Requirements are reviewable artifacts on disk, not chat history.
